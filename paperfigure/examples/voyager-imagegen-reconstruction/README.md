# Voyager imagegen reference reconstruction

A source-registered reconstruction, not a new scientific interpretation of Voyager.
The fixed visual authority is `reference.png` (2061 × 763), copied unchanged from
`../voyager-agent/refinement/design-study.png`. The source was generated by imagegen.
Its original file hash is recorded in `reconstruction-contract.json`.

The only authorized visual change is replacing shaded/gradient fills by flat
colors. Blue identifies curriculum/program-generation work; green identifies
retained state and reusable successful skills; grayscale identifies the runtime
illustration. The source layout, section headings, visible wording, document
panels, icons, arrows, and bottom return route remain the reconstruction targets.
There is no added figure title, caption, or footer.

The current delivery candidate is `output-v10/`. Earlier output revisions preserve
font/rendering failures and repairs; they are not the current delivery.

## Implementation

- `trace-graphics.py` extracts contours from explicitly listed, inspected **icon-only**
  crops and the text-free runtime scene. It never traces text or tiles pixels.
- `traced-graphics.json` retains those vector contours, in source coordinates.
- `rebuild.mjs` authors a common semantic object tree, then emits native SVG and
  native DrawingML using a blank PptxGenJS package. Text is `<text>` / `a:t`;
  objects are native freeform shapes; straight route segments are `p:cxnSp`;
  arrowheads and rounded bends are separately editable native shapes within the
  route group. All module/icon/route groups are real SVG and PowerPoint groups.
- `verify.mjs` inspects the actual generated XML, not just the authoring tree.
  It checks every object's name/type/owner and literal text; the diagnostic
  checker separately audits the SVG against the inventory and frozen PNG hash.

Run from the repository root after `npm ci --prefix paperfigure`:

```sh
# Optional: regenerate the checked-in graphic contours (OpenCV is not a runtime dependency).
uv run --with opencv-python-headless --with numpy python paperfigure/examples/voyager-imagegen-reconstruction/trace-graphics.py

# Use a new revision directory. Existing revisions are never overwritten.
node paperfigure/examples/voyager-imagegen-reconstruction/rebuild.mjs output-new
node paperfigure/scripts/reconstruction-check.mjs --reference paperfigure/examples/voyager-imagegen-reconstruction/reference.png --svg paperfigure/examples/voyager-imagegen-reconstruction/output-new/figure.svg --inventory paperfigure/examples/voyager-imagegen-reconstruction/output-new/inventory.json --out paperfigure/examples/voyager-imagegen-reconstruction/output-new/comparison
```

Render the PPTX independently with LibreOffice (`--headless --convert-to pdf`),
then use `pdftoppm -scale-to-x 2061 -scale-to-y 763 -png -singlefile` to create
`output-new/pptx-render/figure.png`. Both commands should have bounded process
timeouts (60 seconds for LibreOffice, 30 seconds for Poppler). Run:

```sh
node paperfigure/examples/voyager-imagegen-reconstruction/verify.mjs output-new
```

`object-tree.json` preserves all coordinates, editable labels, font properties,
solid fills, and geometry. Regenerate from the authoring source when changing the
layout. For immediate manual editing, open the PPTX, ungroup the relevant semantic
group, and change font/size/content or edit individual shape points. No image layer
needs to be removed before editing text or blocks.

## Explicit limits

- Original font files and metrics are not recoverable from a PNG. Times New Roman
  are approximations. Native SVG uses the `Menlo, DejaVu Sans Mono, monospace`
  chain; native PPTX uses DejaVu Sans Mono. Their compatible sans-mono glyphs and
  source-matched tracking avoid the earlier serif fallback, but exact glyph identity
  is not certified. The licensed regular/bold DejaVu files are in `fonts/`; install
  them on a machine without DejaVu to reproduce PPTX code typography. No global
  fonts were installed or changed during generation.
- Icons retain source-derived silhouettes, with subpixel contour simplification.
  The world-observation landscape retains its gray mountain/sun interior as flat contour layers.
- The Minecraft scene is five flat grayscale contour layers. Character, pickaxe,
  tree, clouds and ground remain, but fine block texture is simplified. These
  paths are editable; editing their detailed contours is more work than editing
  the regular module boxes.
- Route segments and arrowheads are native but deliberately unbound. Moving a
  module does not automatically reroute all attached segments.
- The code and skill names are reproduced as visible source text. They are not
  certified as executable Voyager API signatures. No depicted code was executed.
- LibreOffice rendering is verified; interactive editing/rendering in Microsoft
  PowerPoint has not been tested. Object-native ratios measure representation,
  not visual fidelity or ease of editing.
- PNG difference metrics are diagnostics only, especially after authorized changes
  to flat fills. They are never a fidelity percentage or a venue-quality score.

SVG and PPTX byte reproducibility is checked with normalized package metadata.

The isolated reviewer provides the final source-fidelity verdict separately from
these structural checks. See the hash-bound review in the reviewed output folder.
